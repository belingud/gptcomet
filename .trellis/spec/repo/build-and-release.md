# Build, CI & Release

## Task Runner (`Justfile`)

| Recipe | Runs |
| --- | --- |
| `just help` | recipe list (default goal) |
| `just install` | `uv sync` |
| `just format` | `format-go` + `format-py` |
| `just format-go` | `go fmt ./...` + `goimports -w .` |
| `just format-py` | `uv run ruff format py/` |
| `just check` | `go vet ./...` + `staticcheck ./...` |
| `just ci-check` | `go vet` + `staticcheck` + `uv run ruff check py/` |
| `just test` | `go test ./...` |
| `just test-coverage` / `test-cover-func` | coverage profile → `coverage.html` / per-function |
| `just test-py` / `test-py-cov` | `uv run pytest tests/py_tests/ -v` (+ coverage) |
| `just build` | builds into the path returned by `scripts/get_binary_path.py` |
| `just build-all` | `goreleaser build --snapshot --rm-dist` |
| `just build-py` | `uv build` |
| `just publish-py` | `uv publish` |
| `just release` | `goreleaser release --rm-dist` + `uv publish` |
| `just changelog` | `uv lock` + `git cliff -l --prepend CHANGELOG.md` |
| `just clean` / `coverage` | remove artifacts / open the HTML coverage report |

Notes:

- `just build` resolves its output path through `scripts/get_binary_path.py` →
  `find_gptcomet_binary()`, which **raises if the target binary does not exist yet**. On a fresh
  clone, build with `go build -o py/gptcomet/bin/gptcomet_<arch>_<os>` once, or run
  `go build ./...` for a plain check.
- `--rm-dist` is the legacy goreleaser flag (v2 config in `.goreleaser.yaml`); goreleaser v2 warns
  and suggests `--clean`. Do not "fix" the Justfile alone — CI uses `release --clean`, so align
  both if you touch it.

## CI (`.github/workflows/`)

**`quality.yml`** — runs on push/PR to `master` and `develop` (`tags-ignore: '**'`):

| Job | Steps |
| --- | --- |
| `go-test` | `go test -v -race ./...`, coverage profile, prints total vs the documented 45.7% baseline, uploads to Codecov |
| `go-lint` | `go vet ./...`, `staticcheck` action pinned to `2026.2.2` |
| `python-test` | Python 3.11, `ruff check py/`, `ruff format --check py/`, `pytest tests/py_tests/ --cov=py/gptcomet`, Codecov |

Important consequences: tests run with `-race` (no `-short`), the git identity is configured
globally before tests, and the Python suite runs against an **installed** `gptcomet` wheel-less
source tree (so `tests/py_tests/conftest.py` prepends `py/` to `sys.path`).

**`release.yml`** — runs on tags matching `v*`:

1. `goreleaser` job: `goreleaser release --clean` builds archives
   `gptcomet_<version>_<os>_<arch>.{tar.gz,zip}` (Linux/Windows UPX-compressed, macOS plain),
   `checksums.txt`, and the GitHub release.
2. `check-version` job: a tag ending in `-dev` marks a prerelease (`is_dev=true`).
3. `python-package` job: matrix of `{windows-latest, macos-15-intel, macos-15, ubuntu-22.04}` ×
   Python `3.9–3.13`. It downloads the matching release asset with Nushell, renames it into
   `py/gptcomet/bin/` (`gptcomet_<arch>.exe` / `_mac` / `_linux`), and builds a wheel with
   `uv build --wheel --config-setting=--plat-name=<tag>`.
4. `publish` job: `twine upload` to TestPyPI for `-dev` tags, to PyPI otherwise (environment
   `testpypi` / `pypi`, secret `PYPI_API_TOKEN`).

Wheel platform tags used by CI — keep in sync with `[tool.pdm.build.wheel-data]` in
`pyproject.toml`:

| Runner | Tag |
| --- | --- |
| `windows-latest` | `win_amd64` |
| `macos-15-intel` | `macosx_10_9_x86_64` |
| `macos-15` | `macosx_11_0_arm64` |
| `ubuntu-22.04` | `manylinux2014_x86_64` |

Local `just release` uses `uv publish`; CI uses `twine`. Prefer matching CI when documenting a
release procedure.

## Versioning

Three files carry the version and must agree:

1. `pyproject.toml` → `version = "2.7.1"`
2. `main.go` → `var version = "2.7.1"` (overridden at build time by goreleaser
   `-X main.version={{.Version}}`)
3. `.bumpversion.cfg` → `current_version = 2.7.1`, with `search`/`replace` blocks for the two
   files above

Workflow:

```bash
# 1. bump both files through the tool that understands the pairing
bump2version patch        # or: minor / major
# 2. regenerate the changelog from Conventional Commits (also refreshes uv.lock)
just changelog
# 3. verify, then commit and tag
just test && just check
git commit -am "Bump version: X.Y.Z -> A.B.C"
git tag vA.B.C
```

- `.bumpversion.cfg` has `commit = True` and `tag = True`, so a plain `bump2version` also commits
  and tags — expect that before running it.
- `CHANGELOG.md` is generated by `git cliff` from `cliff.toml`; never hand-edit release sections.
  Commit types filtered out of release notes: `docs:`, `test:`, `ci:`, merge commits.
- `-dev` suffix tags go to TestPyPI (see `release.yml`); do not use `-dev` for a real release.

## Release Checklist

- [ ] Version bumped in `pyproject.toml`, `main.go`, `.bumpversion.cfg` (three-way agreement).
- [ ] `CHANGELOG.md` regenerated with `just changelog` and reviewed; commit messages are
      Conventional Commits.
- [ ] `just ci-check` and `just test` green locally; `just test-py` green.
- [ ] README/README.zh provider tables and `docs/provider-models.md` current.
- [ ] Tag pushed as `vX.Y.Z` (or `vX.Y.Z-dev` for a TestPyPI dry run) and release workflow green.
