# Design — Git hook integration

## Boundaries

| Layer | Files | Responsibility |
| --- | --- | --- |
| CLI | `cmd/hook.go`, `cmd/generate.go` | Cobra shape, flags, user-facing output; delegate all logic |
| Hook domain | `internal/hook/` | script template, install/uninstall/status, prepare-commit-msg run rules |
| VCS | `internal/git/hooks.go` | the only place that shells out for repo root and hooks directory |
| Commit service | `cmd/commit_action.go` | shared `getStagedDiff` + `GenerateMessage` |
| Errors | `internal/errors/templates.go`, `constants.go` | hook-specific `GPTCometError` templates |
| Wiring | `main.go` | register `hook` and `generate` commands |

`internal/hook` imports `internal/git`, `internal/errors`, and `internal/logger`. It does **not**
import `internal/client`, `internal/config`, or `cmd`; the message generator is injected by `cmd`.
This keeps the hook logic testable without a network call.

## VCS helpers (`internal/git/hooks.go`)

```go
// GetRepoRoot resolves the working-tree root for repoPath.
func GetRepoRoot(repoPath string) (string, error)

// GetHooksDir resolves the hooks directory, honoring core.hooksPath and
// linked worktrees.
func GetHooksDir(repoPath string) (string, error)
```

- `GetRepoRoot` runs `git rev-parse --show-toplevel` with `cmd.Dir = repoPath`.
- `GetHooksDir` runs `git rev-parse --path-format=absolute --git-path hooks`; if the Git version
  does not understand `--path-format`, retry `git rev-parse --git-path hooks` and make the result
  absolute relative to the repo root.
- Errors are wrapped with the existing `GitRepositoryNotFoundError` /
  `GitCommandFailedError` templates.
- No other package gains a direct `exec.Command("git", ...)` call.

## Hook domain (`internal/hook`)

```go
type GenerateFunc func(ctx context.Context, repoPath, configPath string) (string, error)

type Manager struct {
    Generate GenerateFunc
}

func NewManager(generate GenerateFunc) *Manager

type InstallOptions struct {
    RepoPath   string
    ConfigPath string
    Force      bool
}

func (m *Manager) Install(opts InstallOptions) (string, error)
func (m *Manager) Uninstall(repoPath string) (UninstallResult, error)
func (m *Manager) Status(repoPath string) (Status, error)
func (m *Manager) Run(ctx context.Context, in RunInput) error
```

```go
type RunInput struct {
    MessageFile string
    Source      string
    RepoPath    string
    ConfigPath  string
}

type Status struct {
    HooksDir   string
    HookPath   string
    State      HookState // missing | installed | foreign
    BackupPath string
}

type UninstallResult struct {
    HookPath string
    Removed  bool
    Restored bool
}
```

### Script template

The installed `prepare-commit-msg` is a POSIX shell wrapper:

```sh
#!/bin/sh
# gptcomet-managed-hook
# Generated by gmsg. Remove with: gmsg hook uninstall

bin="${GMSG_BIN:-gmsg}"
command -v "$bin" >/dev/null 2>&1 || exit 0

config="${GMSG_CONFIG:-<install-time config path>}"

run_hook() {
  if [ -n "$config" ]; then
    "$bin" --config "$config" hook run "$@"
  else
    "$bin" hook run "$@"
  fi
}

if [ "${GMSG_HOOK_DEBUG:-}" = "1" ]; then
  run_hook "$@" || exit 0
else
  run_hook "$@" >/dev/null 2>&1 || exit 0
fi
exit 0
```

- The install-time config path is shell-quoted by Go (`'` escaped as `'\''`) and resolved to an
  absolute path. An empty path leaves `config=""`.
- `GMSG_CONFIG` overrides the embedded path; `GMSG_BIN` overrides the binary.
- Every failure exits `0`; the hook can only delay a commit, never reject it.

### Install / uninstall / status

- Resolve `hooksDir` with `git.GetHooksDir`; hook file is `prepare-commit-msg`.
- `mkdir -p hooksDir`, read the existing file:
  - missing → write managed script with `0755`;
  - contains `# gptcomet-managed-hook` → overwrite (idempotent);
  - foreign → return `HookAlreadyExistsError` unless `Force`;
  - `Force` → copy the original bytes to `prepare-commit-msg.gptcomet-backup` (error if the
    backup already exists), then write the managed script.
- `Status` classifies the file as `missing`, `installed`, or `foreign` and reports the backup path.
- `Uninstall` removes only a managed file and restores the backup when present. A foreign hook is
  reported as not removed and is never deleted.

### `Run` rules

1. `GMSG_SKIP` truthy → return nil.
2. `force := GMSG_FORCE` truthy.
3. If not `force` and `Source` is `merge`, `squash`, `commit`, or `message` → nil. `template`
   is allowed: the all-comment template used by the first commit should be filled, while a
   template with real content is caught by the content check in step 4.
4. Read `MessageFile`; if not `force` and it has any non-comment, non-blank line → nil.
5. `repoRoot, _ := git.GetRepoRoot(in.RepoPath)`; generate with
   `m.Generate(ctx, repoRoot, in.ConfigPath)`.
6. If generation fails, returns an error; the command layer logs at debug and exits successfully.
7. Compose `message + "\n\n" + preserved comments` (normal path preserves the whole original file
   because it is comment-only; force path keeps only lines starting with `#`).
8. Preserve the existing file mode, default `0644`; write atomically when practical
   (`os.WriteFile` is acceptable for a single small file).

`#` is the only comment character in v1; custom `core.commentChar` is documented as a limitation.

## Commit service refactor (`cmd/commit_action.go`)

Extract the duplicated staged-diff preamble:

```go
func (s *CommitService) getStagedDiff() (string, error)
func (s *CommitService) GenerateMessage() (string, error)
```

- `getStagedDiff` performs `HasStagedChanges` → `GetStagedDiffFiltered` → non-empty check and
  returns `NoStagedChangesError` for empty results.
- `GenerateMessage` calls `getStagedDiff`, `generateCommitMessage`, then `removeThinkTags`.
- `Execute` keeps its progress UI but delegates the diff fetch to `getStagedDiff`.
- `handleCommitInteraction` retry reuses `getStagedDiff`.
- Existing behavior and error strings stay unchanged.

## `gmsg generate` output contract

`cmd/generate.go`:

- Flags: `--repo`, `--rich`, plus `AddAdvancedAPIFlags`. Git only; SVN generate is out of scope.
- Builds a `CommitService` with the root `--config` value.
- Runs generation inside a helper that temporarily assigns `os.Stdout = os.Stderr` and restores it
  with `defer`. This swallows the known `fmt.Printf` status/usage lines from `BaseLLM.MakeRequest`
  and a few providers.
- Prints only the returned message with `fmt.Fprintln(cmd.OutOrStdout(), msg)`.
- Errors propagate to Cobra; stdout stays clean on failure.

## CLI wiring (`cmd/hook.go`, `main.go`)

- `NewHookCmd()` returns a parent `hook` command with `install`, `uninstall`, `status`, and hidden
  `run` subcommands.
- `install` flags: `--repo` (default `.`), `--force`; reads the root `--config` persistent flag.
- `uninstall` / `status` flags: `--repo`.
- `run` takes `cobra.RangeArgs(1, 3)`, a `--repo` defaulting to `.`, and is `Hidden: true`.
- The command layer constructs `hook.NewManager` with a closure that builds `CommitService` and
  calls `GenerateMessage`. On `Run` errors it logs debug and returns nil, preserving fail-open.
- `main.go` registers `cmd.NewHookCmd()` and `cmd.NewGenerateCmd()`.

## Error templates

Add to `internal/errors/constants.go` + `templates.go`:

- `HookAlreadyExistsError(path, backupPath string)` — Git error; suggests inspecting/merging the
  existing hook or rerunning with `--force`.
- `HookBackupExistsError(path string)` — validation error; suggests moving/removing the stale
  backup.
- `HookInstallError(path string, cause error)` and `HookUninstallError(path string, cause error)` —
  Git errors wrapping filesystem failures with `%w`.

`hook run` generation failures are not user-facing errors (fail-open); the command logs at debug.

## Testing

- `internal/git/hooks_test.go`: temp repo, `core.hooksPath` override, non-repo error, worktree path
  if cheap.
- `internal/hook/hook_test.go`:
  - install creates executable managed script; rerun idempotent;
  - foreign hook error + original bytes unchanged; `--force` backup; uninstall restore;
  - status states;
  - run matrix with a stub `GenerateFunc`: all skip conditions, `GMSG_FORCE`, comment
    preservation, empty message, generator error, file unchanged on error;
  - script contains marker, config path, and expected `hook run` invocation.
- `cmd/hook_test.go`: command construction, hidden run, fail-open behavior with a stub manager
  where practical.
- `cmd/generate_test.go`: output helper forwards only the message; flags parse; no staged diff
  error path.
- Manual: temp repo `install → status → uninstall`, a fake `gmsg` in `PATH` for the script path.

## Compatibility & rollback

- No config keys, providers, or LLM behavior change.
- Existing `gmsg commit` output is unchanged; only internal diff fetching is extracted.
- Hook installation is opt-in per repo; `gmsg hook uninstall` removes the managed file and restores
  a backup. There is no data migration.
- If the feature misbehaves, deleting the hook file or running uninstall restores normal Git
  behavior. The release is not part of this task.

## Trade-offs

- A thin shell wrapper + Go `hook run` keeps logic testable and consistent with the CLI; it adds one
  hidden command but avoids fragile shell conditionals.
- `os.Stdout` redirection is a deliberate local workaround for existing provider prints; changing
  every provider to use stderr is a separate cleanup.
- Synchronous generation is the simplest UX (message is ready when the editor opens), at the cost
  of commit latency; the existing timeout bounds it.
