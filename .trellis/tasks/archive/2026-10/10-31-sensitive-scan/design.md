# Design — Sensitive data pre-send scanning

## Boundary

New leaf package `internal/secretscan` owns everything about detecting and rewriting secrets in a
diff. It imports only the standard library plus `internal/errors` (for the block error) and must
never import `internal/config`, `cmd`, or network packages. Everything user-facing stays in `cmd`.

```
cmd/commit_action.go ─┐
cmd/review.go ────────┼─► internal/secretscan (diff parser → matcher → modes/redaction)
cmd/hook.go ──────────┘             │
                                    └─► internal/errors.SensitiveContentError
```

The diff is intercepted **after** `file_ignore` filtering and **before** the request is built:

- `CommitService.getStagedDiff()` — covers `commit`, `generate`, hook, and retry.
- `ReviewService.getDiff()` — covers staged review and piped stdin review.

No changes to `internal/client`, `internal/llm`, `internal/git`, or `file_ignore` behavior.

## Public API (`internal/secretscan`)

```go
type Mode string

const (
    ModeOff    Mode = "off"
    ModeWarn   Mode = "warn"
    ModeRedact Mode = "redact"
    ModeBlock  Mode = "block"
)

func ParseMode(s string) (Mode, error) // trims + lowercases; rejects unknown values

type Options struct {
    Mode  Mode
    Allow []string // user regexes; match against secret or full line → ignore finding
}

type Finding struct {
    RuleID    string
    Path      string
    Line      int    // 1-based new-file line; 0 for file-level findings
    Column    int    // 1-based byte column in the added line content
    FileLevel bool    // true for sensitive-file rules
    Secret    string // raw; never printed outside this package
    LineText  string // raw added line (without '+' prefix)
}

type Result struct {
    Diff     string    // possibly redacted diff to send
    Findings []Finding // always populated, for warnings and errors
}

// Apply scans added lines and returns the diff that should be sent.
// warn  → Diff unchanged, Findings populated
// redact→ Diff rewritten, Findings populated
// block → Diff empty, findings + *errors.GPTCometError returned
// off   → no scanning, Diff unchanged, nil findings
func Apply(diff string, opts Options) (Result, error)
```

A diff without any `@@`/`+++` structure (for example raw text piped into `gmsg review`) is treated
as a single `stdin` pseudo-file so the same rules still apply.

## Diff parser

Line-oriented state machine over the unified diff:

- track the current path from `+++ b/<path>` (`/dev/null` → no added lines),
- track the next new-file line number from `@@ -a,b +c,d @@`,
- collect only lines that start with `+` and are not the `+++` header (strip exactly the first
  byte), recording `(path, newLine, diffLineIndex, contentOffset)`,
- skip binary diffs (`GIT binary patch`, `Binary files ... differ`),
- ignore `\ No newline at end of file`.

Testing seam: the parser returns `[]addedLine`; the matcher and redactor both take that slice, so
tests can assert on it directly without regex fixtures.

## Rule data and matcher

### Vendored data

- `internal/secretscan/rules/gitleaks.toml` — gitleaks v8.30.1 `config/gitleaks.toml`
  (MIT, 222 rules, ~95 KB), unmodified.
- `internal/secretscan/rules/LICENSE` — gitleaks MIT license text (Zachary Rice).
- `internal/secretscan/rules/UPSTREAM.md` — version, commit, sha256, update instructions.
- `internal/secretscan/rules_gen.go` — **generated**, holds `var gitleaksRules = []rule{...}`.
  Header records "Code generated by scripts/gen_secret_rules.py; DO NOT EDIT" and the upstream
  version. Rule regex strings are ~24 KB total; generated Go stays small.

`scripts/gen_secret_rules.py` (Python 3.11+ stdlib `tomllib`, maintainer-only) converts the TOML
into Go struct literals. `just sync-secret-rules` regenerates the file from the vendored TOML and
runs `gofmt`. No TOML parser or other dependency at build/runtime.

### Matcher

`rule` mirrors the TOML fields the default set uses: `id`, `regex`, `secretGroup`, `entropy`,
`keywords`, `path`, `allowlists[]` (`condition` AND/OR, `paths`, `regexes`, `regexTarget`
match/line/secret, `stopwords`). Rule descriptions/tags are not embedded because the scanner does
not render them.

Per file (one added-line blob per file, lines joined with `\n`):

1. path gate: rule with `path` must match the file path; path-only rules (no regex) produce a
   file-level finding at the first added line.
2. keyword prefilter: case-insensitive substring check for the rule's keywords against the blob;
   no keyword hit → skip the regex entirely (keeps 222 rules cheap, compiles regex lazily).
3. regex `FindAllStringIndex`; extract `secretGroup` if set; skip when
   `shannonEntropy(secret) < entropy`.
4. allowlist: AND/OR over the configured checks (regexes with `regexTarget`, stopword substrings
   on the secret, paths on the file path; commits are not applicable and ignored).
5. user allowlist (`Options.Allow`): regex matched against the secret or the full line.

Local path rules are appended in handwritten `rules.go`, not the generated file:

| Rule ID | Match |
| --- | --- |
| `sensitive-env-file` | `(?i)(?:^|/)\.env(?:\.[^/]+)?$` |
| `sensitive-private-key-file` | `(?i)(?:^|/)id_(?:rsa\|ed25519\|ecdsa\|dsa)$`, `*.pem`, `*.key`, `*.p12`, `*.pfx` |
| `sensitive-credential-file` | `(?i)(?:^|/)(?:credentials(?:\.json)?\|\.npmrc\|\.pypirc\|\.netrc)$` |

Dedupe by `(ruleID, path, line, column)`; sort by path/line/column/ruleID for stable output.

## Modes and redaction

- `warn`: return diff unchanged; the caller prints masked findings to stderr.
- `redact`: rewrite the **added lines of the diff that will be sent**. Per line, replace each
  finding span with `[REDACTED:<rule-id>]`; file-level findings replace the whole added content
  with `[REDACTED:<rule-id>]`. Multiple/overlapping spans on one line are applied right-to-left.
  Line count and hunk headers are preserved because only content bytes change.
- `block`: print findings (caller) and return
  `errors.SensitiveContentError([]errors.SensitiveFinding)`; no request is made.
- `off`: no scan.

Masked preview helper: keep ≤ 4 leading and ≤ 4 trailing characters, replace the middle with `…`;
short secrets are fully masked. The raw `Secret` field is never formatted into any message.

## Config and CLI

Defaults (`pkg/config/defaults`): `DefaultSensitiveMode = "warn"`;
`DefaultConfig["sensitive"] = {"mode": "warn", "allow": []}`.

`internal/config`:
- `GetSupportedKeys()` adds `sensitive.mode`, `sensitive.allow`.
- `Validate()` rejects unknown `sensitive.mode` and non-string entries / invalid regexes in
  `sensitive.allow`.
- No `ManagerInterface` change: the command layer resolves options through the existing
  `GetWithDefault` seam, matching how `output.*` values are read in `cmd/commit_action.go`.

`cmd/sensitive.go` (new): `resolveSensitiveOptions(cfgManager, override)` reads
`sensitive.mode` (default from defaults) and `sensitive.allow`, parses the mode, compiles allow
regexes, and turns invalid values into `errors.InvalidSensitiveModeError` /
`errors.InvalidSensitiveAllowError` templates. `printSensitiveFindings(w, findings, mode)` renders
the masked warning block.

Flags: `--secrets <off|warn|redact|block>` added to the general flag sets of `commit`,
`generate`, and `review`; `CommitOptions`/`ReviewOptions` carry `SecretsMode string` and pass it to
`resolveSensitiveOptions`. Empty flag → config value.

## Service integration

- `CommitService.getStagedDiff()`: after enforcing non-empty staged changes, call
  `Apply(diff, options)`, print findings when `warn`/`redact` (or before block error) to
  `s.stderr`, return `Res.Diff`. The service gains `stderr io.Writer` (default `os.Stderr`) so
  tests capture warnings. `GenerateMessage` and `Execute` share this path, so the hook and retry
  are covered automatically.
- `ReviewService.getDiff()`: same treatment for both piped input and staged diff; the service
  gains `stderr io.Writer`.
- Warning format (stderr):
  ```
  ⚠ Sensitive data detected (2 finding(s), mode: warn):
    • .env:3  [sensitive-env-file]  (file-level)
    • config.go:12  [openai-api-key]  sk-1…abcd
  ```
- `generate`'s stdout contract is preserved: warnings go to stderr only.

## Errors

`internal/errors/constants.go` + `templates.go`:

```go
func SensitiveContentError(findings []SensitiveFinding) *GPTCometError
func InvalidSensitiveModeError(value string) *GPTCometError
func InvalidSensitiveAllowError(pattern string, err error) *GPTCometError
```

Type `validation`; suggestions: unstage the file (`git restore --staged <path>`), switch to
`redact` (`gmsg config set sensitive.mode redact`), allow a known placeholder
(`gmsg config append sensitive.allow '<regex>'`), or bypass once (`--secrets off`). The error
message lists masked findings only.

## Tradeoffs / compatibility

- Full gitleaks engine features that do not affect the default rule set are intentionally omitted
  (base64/hex decoding, archives/history, baselines, required rules). Coverage for encoded secrets
  inside ordinary diff text is therefore lower than gitleaks; documented in the README section.
- `sensitive.allow` is evaluated against both secret and line, a superset of gitleaks
  `regexTarget` semantics, so users can silence either a value or a surrounding placeholder.
- New config keys are additive; old configs keep working (missing section → defaults).
- Rollback is `sensitive.mode: off` (runtime) or reverting the single feature commit (no schema
  migration, no persisted state).
